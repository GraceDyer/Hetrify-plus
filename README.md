## README

### Running Environment

We recommend using Docker to set up the running environment. The provided Docker image contains all necessary tools, libraries, experimental data, and the Hetrify tool.

#### Using Docker

1. Pull the Docker image:

```sh
docker pull anonymous535/hetrify-plus:latest
```

2. Run the Docker container:

```sh
docker run -it --name hetrify_container -u root anonymous535/hetrify-plus:latest /bin/bash
cd ~
```

The Docker container includes all dependencies and tools, along with the experimental data and Hetrify tool under the home directory.

#### Manual Setup (if not using Docker)

If you prefer manual setup on Ubuntu 22.04 or a compatible Linux distribution, install the following:

1. Python 3.10 (including `venv` and `dev`)
2. CBMC 5.95
3. RISC-V GNU Toolchain
4. libxml2
5. libelf (development package)
6. Python packages: `tqdm`, `pyelftools`
7. Rust (rustc) with RISC-V target support

Setup commands:

```sh
sudo apt-get update
sudo apt-get install -y build-essential curl wget tar python3.10 python3.10-venv python3.10-dev bash-completion libxml2 libelf-dev python3-pip

pip3 install tqdm pyelftools

wget https://github.com/diffblue/cbmc/releases/download/cbmc-5.95.1/ubuntu-22.04-cbmc-5.95.1-Linux.deb
dpkg -i ubuntu-22.04-cbmc-5.95.1-Linux.deb

wget https://github.com/riscv-collab/riscv-gnu-toolchain/releases/download/2023.01.31/riscv64-elf-ubuntu-22.04-nightly-2023.01.31-nightly.tar.gz
tar -xvf riscv64-elf-ubuntu-22.04-nightly-2023.01.31-nightly.tar.gz
sudo mv riscv64-unknown-elf /opt/riscv
echo 'export PATH=/opt/riscv/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
```

### Directory Structure

* **EX1**: Datasets and results for Experiment 1 in the paper, including assembly programs, generated C code, and verification results.
* **EX2**: Datasets and results for Experiment 2 in the paper.
* **EX3**: Datasets and scripts for the new experiment based on HumanEval-style C code generation, compilation, lifting, and test execution.
* **EX4**: Datasets and results for comparison experiments between Hetrify, IDA Pro, and Ghidra (previously Experiment 3).
* **Hetrify**: The verification transformation tool designed in our ICSE paper.
* **Hetrify+**: The verification transformation tool designed in this paper.
* **ae**: Auxiliary binary analysis tool invoked internally by Hetrify.

---

### Supported Functions of Hetrify+

Hetrify and Hetrify+ support transforming the following types of code:

* Binary programs (`.elf`)
* RISC-V assembly programs (`.s`)
* C programs (`.c`)
* C mixed with assembly programs (`.c`)
* RISC-V static library code (`.a`)
* Rust programs (`.rs`)

---

### Basic Usage of Hetrify+

Assume you want to verify the program `./bAnd1.s`:

```sh
./Hetrify+ ./bAnd1.s
```

This generates `bAnd1_gen.c` in the current directory. You can then verify it with CBMC:

```sh
cbmc ./bAnd1_gen.c --unwind 20
```

To view additional functions and usage:

```sh
./Hetrify+
```

## Experiment 1

All files for Experiment 1 are stored in the `EX1` folder. The assembly code to be verified is under `ASM`. The C code generated by Hetrify is under `Hetrify/F` and `Hetrify/T`. The C code generated by Hetrify+ is under `Hetrify+/F` and `Hetrify+/T`, together with result files.

You can use `solve.py` to verify the converted C programs.

### Example Usage

Verify all files in `Hetrify+/F` with loop unwind 50:

```sh
cd EX1
python3 solve.py Hetrify+/F H+F50.csv 50 3000
```

This produces `H+F50.csv` recording the verification results.

## Experiment 2

All files for Experiment 2 are stored in the `EX2` folder. This experiment focuses on heterogeneous programs with missing critical function source code, including static libraries with missing functions, converted C code, and result files. Use `solve.py` to verify converted programs under `Hetrify/F`, `Hetrify/T`, `Hetrify+/F`, and `Hetrify+/T`.

### Example Usage

Verify all files in `Hetrify+/T` with loop unwind 100:

```sh
cd EX2
python3 solve.py Hetrify+/T H+T100.csv 100 3000
```

This produces `H+T100.csv`.

## Experiment 3 (New)

All files for the new experiment are stored in the `EX3` folder. This experiment generates HumanEval-style C tasks using GPT-4o, builds a benchmark dataset, compiles source code, lifts binaries back to C using Hetrify or Hetrify+, and finally runs test cases to evaluate correctness.

### EX3 Directory Contents

* `build_c_humaneval.py`
* `genBanchmark.py`
* `run_hetrify.py`
* `run_gcc.py`
* `run_out.py`
* `data/`
* `result/`

### Step 1: Generate HumanEval-style C Tasks

`build_c_humaneval.py` calls GPT-4o to generate qualified C programs. After execution, it generates `c_humuaneval.jsonl`.

```sh
cd EX3
python3 build_c_humaneval.py
```

Output:

* `c_humuaneval.jsonl`

### Step 2: Build the Benchmark Dataset

`genBanchmark.py` parses `c_humuaneval.jsonl` and produces a `C_tasks/` folder containing the C benchmark tasks.

```sh
cd EX3
python3 genBanchmark.py
```

Output:

* `data/C_tasks/`

### Step 3: Lift with Hetrify or Hetrify+

`run_hetrify.py` compiles each C task and then lifts the produced binaries back into C using Hetrify or Hetrify+.

Example command:

```sh
cd EX3
python3 ./run_hetrify.py data/C_tasks data/Hetrify ../Hetrify data/Hetrify_log
```

This produces:

* lifted C files under `data/Hetrify/`
* logs under `data/Hetrify_log/`

If you want to use Hetrify+, replace `../Hetrify` with the corresponding executable path, for example `../Hetrify+`.

### Step 4: Compile Lifted C Code with Test Files

`run_gcc.py` compiles the lifted C code together with its test file and outputs compilation results.

```sh
cd EX3
python3 ./run_gcc.py data/Hetrify result/Hetrify_gcc.csv
```

Output:

* `result/Hetrify_gcc.csv`

### Step 5: Execute Tests

`run_out.py` runs each compiled executable and checks whether test cases pass.

```sh
cd EX3
python3 ./run_out.py data/Hetrify result/Hetrify_test.csv
```

Output:

* `result/Hetrify_test.csv`

## Experiment 4 (Previously Experiment 3)

All files for this experiment are stored in the `EX4` folder. It contains datasets and results for comparison experiments between Hetrify, IDA Pro, and Ghidra. The `solve.py` script compares analysis results across these tools. Input files are located in the `Ghidra`, `Hetrify`, and `Hetrify+` subfolders.

### Example Usage

Compare all files in `Ghidra/T` and store the output in `GT200.csv`:

```sh
cd EX4
python3 solve.py Ghidra/T GT200.csv 200 3000
```

This produces `GT200.csv` containing the comparison results.
